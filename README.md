# Escapement: privacy-preserving token vesting for LEZ v0.4

**Grant reviewers: [start here for a 10-minute verification path and the honest limits](docs/START-HERE.md).**

Escapement is a token vesting program for the Logos Execution Zone (LEZ), written against LEZ's
v0.4 actor model (`v0.4.0-rc3`), for [Logos RFP-017](https://github.com/logos-co/rfp/blob/master/RFPs/RFP-017-token-vesting.md).
A creator locks native LEZ or tokens in a program-owned escrow against a cliff + linear, linear, or
milestone schedule; the beneficiary claims what has vested, in one transaction, either to a public
account or to a private account under a one-time alias, so the destination and later movements are
not recorded in public on-chain state. Schedule terms stay public, as the RFP specifies.

Dual-licensed MIT OR Apache-2.0. **Not audited.**

## Quickstart

Needs Rust 1.98.1 (`rust-toolchain.toml`), RISC Zero 3.0.5 (`rzup install r0vm 3.0.5`,
`rzup install rust 1.91.1`, `rzup install cpp 2024.1.5`), and for the sequencer suite
`libpcsclite-dev`, `pkg-config`, `protobuf-compiler` and `jq`.

```sh
# Unit, property, SDK, IDL and in-process integration tests on LEZ v0.4.0-rc3's state machine
RISC0_DEV_MODE=1 cargo test --workspace --locked -- --nocapture

# The guest is reproducible: rebuild it and compare with image-ids.tsv
scripts/build-guest.sh --check

# The IDL is generated, not written: check it (or regenerate with -- --write)
cargo run -p escapement-idl --bin idl

# End-to-end on a local standalone sequencer (loopback only); E2E_DEV_MODE=0 for real proofs
e2e/sequencer.sh build
E2E_DEV_MODE=1 e2e/run_e2e.sh
```

## Using the CLI against a local sequencer

`e2e/sequencer.sh start` runs a standalone sequencer on `127.0.0.1:3040` from LEZ's `local.json`;
the CLI talks only to loopback and, by default, signs with LEZ's published local test key.

```sh
e2e/sequencer.sh start
alias esc='e2e/sequencer.sh cli'
esc deploy target/riscv-guest/escapement-methods/escapement-guest/riscv32im-risc0-zkvm-elf/release/escapement.bin \
    --init-admin --keys-out e2e/.run/deploy.json          # immutable; prints the program address
export ESCAPEMENT_PROGRAM=<program address> \
       ESCAPEMENT_ELF=target/riscv-guest/escapement-methods/escapement-guest/riscv32im-risc0-zkvm-elf/release/escapement.bin
esc create --beneficiary <account> --total 1000000 --linear <start_ms>,<end_ms>
esc show --schedule <schedule>                            # claimable now, next unlock, tranches
ESCAPEMENT_KEY=<beneficiary key> esc claim --schedule <schedule> --to <account>

# A private claim goes only to a private account whose keys you hold:
ESCAPEMENT_KEY=<beneficiary key> esc private-account new --out my-account.json   # keys, mode 0600
ESCAPEMENT_KEY=<beneficiary key> esc claim --schedule <schedule> --to-private my-account.json
#   -> prints the privacy disclosure for this exact claim and its confirmation token; sends nothing
ESCAPEMENT_KEY=<beneficiary key> esc claim --schedule <schedule> --to-private my-account.json --confirm <token>
ESCAPEMENT_KEY=<beneficiary key> esc private-account show --file my-account.json  # balances, on chain?
esc cancel --schedule <schedule>
e2e/sequencer.sh stop
```

Each private transaction spends from the account state recorded in the key file and records the
new state (decrypted from the account's own note), so the funds stay spendable by whoever holds
the file. For token schedules, deploy the token program the same way and set
`ESCAPEMENT_TOKEN_PROGRAM` and `ESCAPEMENT_TOKEN_ELF`; a private account then needs a native
balance for fees (`private-account shield --file F --amount N`) and a private holding of the token
(`private-account init-holding --file F --definition D`) before its first token claim. The full
sequence, as run in CI, is `e2e/run_e2e.sh`.

`--dry-run` is available on create, claim, cancel, make-non-cancelable, signal,
transfer-beneficiary, withdraw-fees and batch; unknown flags are refused. `batch` creates several schedules
on one escrow in one transaction. Program addresses on LEZ testnet 0.4 will be listed here once it
launches; on the public network above: [docs/PUBLIC-NETWORK.md](docs/PUBLIC-NETWORK.md).

## Privacy, in short

Recorded in public on-chain state: the schedule's terms and beneficiary address, each claim's amount
and time (`Claimed` event), a one-time alias as a private claim's destination, and the fee reserve.
Not recorded in public on-chain state: which private account receives a private claim, its balance,
and later private movements. The beneficiary's link to the schedule is public by design (RFP-017,
"Privacy limitation"). Details: [docs/events.md](docs/events.md) and the disclosure text in
`crates/escapement-sdk/src/disclosure.rs`.
